共通調査契約:

前提:

* 公開情報だけで埋める。
* 各項目の意味、型、列挙値、禁止事項は対象 schema / model の `description` と `x-do_not` に従う。
* schema の enum は閉じた値集合として扱い、source の用語に対応する値がない場合に値を作ったり、名前の近い別の値へ読み替えたりしない。
* 見つからない値は推測で埋めず、記録の一覧を空にし（Missing）、`note` に事情を自由記述する。値がある場合も、値を誤解しうる事情があれば `note` に書く。
* 応募開始日・締切日に限り、sourceが当該募集回の日付を未定・後日案内と明示する場合は `records=[]` と `announced_later`（sourceとretrieval付き）で記録し、`note`も残す。記載がないだけの場合と区別し、取得経路は日付と同じ規則で保持する。
* source の解釈や、source 内の別箇所の記述を組み合わせた展開は裁量で行ってよい。行った場合は `note` に書く。
* 記録へ入れるのは、開いたsourceが対象企業、応募枠（年度を含む）、および選考種別を対象としており、値を直接記述している場合だけとする。そのsourceが参考として示す過去の実績も、その応募枠の値として記録してよい（何年の実績かをnoteに書く）。

確認する source:

* 次に挙げる source は、対象 schema に該当しうる項目があれば、公式 source で値を確認できたかにかかわらず、すべて必ず開いて確認する。名前を挙げたサイトは対象企業のページを開き、種類だけを挙げたものは検索する。どのページをどこまで見るかは任せる。
* 括弧内の項目は、そのsourceに主に載っている項目の目安であり、確認する項目をそれに限らない。
* 公式 source:
  * 企業公式の企業概要、会社情報、会社案内、沿革、事業紹介、グループ会社一覧。
  * 企業公式の IR、有価証券報告書、統合報告書、サステナビリティレポート、ESG データ、人的資本データ、コーポレートガバナンス報告書。
  * 企業公式の採用ページ、募集要項、採用 FAQ、働き方紹介、制度紹介、募集案内 PDF。
  * 企業本人が掲載・管理している就活サイト上の募集情報や企業ページ（マイナビ、リクナビなどの企業掲載ページを含む。初任給・募集要項）。
  * 法令に基づく開示・公表：EDINET の有価証券報告書、gBizINFO、法人番号公表サイト、女性の活躍推進企業データベース、しょくばらぼなど官公庁のデータベース。
  * 企業公式のニュースリリース、社長メッセージ、研究ページ、技術ページ。
* 非公式 source:
  * OpenWork、転職会議、en Lighthouse、就活会議（年収・残業・休日・離職などの働き方）。
  * ONE CAREER、外資就活ドットコム、就活会議、みん就、unistyle の選考体験記（選考工程。応募枠の年度ごとに確認する）。
  * シメナビ（simenavi.com）などの締切集約サイト、外資就活ドットコムの募集情報ページ、ONE CAREER の締切情報（応募開始日・締切日）。
  * doda などの求人集約サイト。
  * 報道記事、業界データベース、第三者まとめ記事。
  * 個人の選考体験記、就活ブログ、SNS の投稿。

調査方針:

* 非公式 source は、公式 source で値を確認できたかにかかわらず常に調べる。非公式 source で確認できた値は、source の kind を unofficial として、公式 source の records とは別の record に保持する（公式 source の値を置き換えない）。公式・非公式のどちらでも確認できない場合だけ missing を確定する。
* 複数 source の記述が食い違う場合は、source を分けて records に保持するか、判断不能なら missing にする。

調査ルール:

* 入力された `company_id` と `legal_name` が指す対象法人からずれない。
* 企業名が曖昧でも、入力の `legal_name` と一致する法人を前提に調査する。
